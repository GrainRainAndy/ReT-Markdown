# 样式扩展后续里程碑

这是验收报告 X04–X06 的后续交付计划，尚未实现，不属于 alpha.2 的已完成能力。本轮先修复 B01–B07 和生命周期风险，再交付 X01–X03 的编辑与视觉证据，之后进入本里程碑；不以主题功能替代正确性验收。

## 实施顺序和交付物

| 顺序 | 实现内容 | 交付与验收条件 |
| --- | --- | --- |
| S1 / X05 | 版本化样式边界 | 发布 Style API v1：内容根、标题/正文/列表/引用/代码/表格/公式选择器，字号/行高/宽度/间距/前景/背景/链接令牌；说明兼容与弃用策略。关键恢复/关闭/权限 UI 不进入用户样式作用域。 |
| S2 / X04 | 用户主题文件与入口 | 用户目录与应用包分离；主题选择、打开目录、CSS 编辑/导入、重新加载、预览、恢复默认。附一个独立示例主题和最小 README；选择持久化，升级不覆盖用户文件。 |
| S3 / X04–X05 | 加载、失败与安全 | 缺失/格式错误/超预算时显示原因、恢复内置默认且可重试。资源仅解析为主题目录内的本地静态资源；拒绝路径穿越、符号链接逃逸、远程 URL、远程 import 和脚本。修改主题不改 Markdown、dirty、历史或选区。 |
| S4 / X06 | 屏幕与打印验证 | 第一阶段用户主题只作用于屏幕，PDF 明确使用内置固定打印样式：A4 纵向、四边 20 mm、白底。以后若加入主题打印，另设显式选项和回退，不继承屏幕宽度/外边距。 |

实施前在独立技术设计中冻结 API 的实际名称和资源限制，示例只使用已公布 API，不直接复制 Typora 主题。对不兼容版本给出明确错误，未知可选令牌忽略并保留内置值；每次升级以旧版示例验证兼容。

## 必须保留的回归证据

1. 同一文稿加载、切换、编辑、重新加载和重启恢复主题，逐次比较源字节、revision、dirty、正反选区和撤销栈；均保持不变。
2. 删除主题文件、损坏清单、非法 CSS、不可用字体、越界资源与离线环境都有可见回退；关键错误提示仍可读、可操作。
3. 应用包更新前后用户 CSS 哈希相同，选择仍能解析；缺失主题落回内置 Github。
4. 示例主题覆盖正文、代码、数学和表格；窄窗/宽窗、浅/深色与辅助功能对比检查。
5. 在同一候选包导出中文、长代码、跨页表格、图片与宽公式，核对 A4/20 mm、文本完整和分页；切换屏幕主题不改变默认打印几何。

完成 S1–S4 后形成独立实现报告并报送验收；当前不承诺未经验证的主题兼容性。
