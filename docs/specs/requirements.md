# ReT Markdown 从零重写需求分析

日期：2026-10-21。状态：用户已批准按本基线进入实现，初版产出后体验评审。此次重写从独立空分支开始，旧版本已[归档](../legacy-archive.md)。本文重新定义产品行为，不继承旧实现的模块划分或技术选型。

用户明确要求的是：完整重写、用 REA 研究仓库内 Typora 副本、重新编写需求与技术方案；并在本轮确认“保留个人 macOS Markdown 编辑器定位，彻底重写实现”。以下细化规则作为新的评审草案，不表示旧方案的全部决策再次获批。技术选择见[技术方案](../architecture/technical-design.md)。

## 1 目的与成功标准

产品服务于中文课程笔记、包含公式与代码的技术文档和长文写作。普通 `.md` 文件是用户交付物，编辑器应让用户直接操作标题、段落、列表、表格等文档结构，并能随时查看和修改真实源文。

成功标准包括：连续写作时光标位置可预期；中文组词不中断；任何内容修改可解释、可撤销；未修改区域保持原样；保存、恢复与资源迁移不丢数据；导出与编辑使用同一语义。单次截图相似或若干单元测试通过不足以证明达到这些标准。

优先级顺序为：数据完整性与输入正确性 → 选区和结构编辑一致性 → 文件工作流 → 视觉与性能。核心质量属于必需条件，不能放入“后续优化”。

## 3 用户工作流

| 场景 | 完整流程 | 成功条件 |
| --- | --- | --- |
| 课堂笔记 | 新建 → 中文输入 → 列表/公式 → 粘贴截图 → 首次保存 → 重开 | 文字、层级、公式与图片全部可恢复 |
| 修改已有文档 | Finder 打开 → 只改一段 → 源码核对 → 保存 | 未修改区域字节不变，外部工具仍能读取 |
| 连续技术写作 | 在正文/代码/公式/表格间移动 → 编辑 → 撤销 → 模式切换 | 内容、选区、焦点及历史相互一致 |
| 长文整理 | 查找隐藏语法 → 全部替换 → 撤销 → 导出 | 替换范围明确；导出采用一个固定版本 |
| 异常恢复 | 保存失败或渲染进程退出 → 重试/重载 → 恢复 | 不用旧快照覆盖新编辑，不把失败伪装为已保存 |

## 4 内容与格式

### R-DOC-01 文件格式和保真

支持 `.md` 与 `.markdown`，新文件 UTF-8、无 BOM、LF；新建内容不自动添加尾部换行。已有文件保留 UTF-8 BOM、每一处 LF/CRLF、末尾换行以及未知语法。非法 UTF-8 明确拒绝编辑并保留原文件，不替换成乱码后保存。

不编辑时，保存、模式切换、主题切换和导出均不得改变文件字节。局部编辑只允许改变目标范围和使该操作语法成立所需的最小范围；结构操作须在用例中声明允许改写的容器。例如移动列表子树可以改写被移动子树的前缀，不能顺带重排整篇文档。

保真需要保留语法分隔符、转义、空白与原始片段，不只保留渲染后的 AST。保存不得依赖整篇 HTML 转 Markdown，也不得为了渲染方便重排未编辑内容。

### R-DOC-02 方言与未完成内容

语法基线选用 [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)，加选定的 [GFM 扩展](https://github.github.com/gfm/)：表格、任务列表、删除线和自动链接。GFM 文档基于旧版 CommonMark；有冲突时以项目固定的方言夹具为最终契约，不宣称等同 GitHub 网站的全部行为。

数学为项目扩展：未转义且不在代码中的 `$…$` 为行内数学候选，内侧首尾不得为空白、不得跨行；紧接闭合符后的数字排除该候选，减少货币误识别。独占一行的 `$$` 围住块数学；块内不运行 Markdown 列表/强调规则。歧义样本（货币、转义美元、连续美元）必须固定在方言夹具中，渲染与编辑共用判定。

未闭合围栏、未闭合公式、编辑中的表格、YAML 元数据和未支持扩展均可作为原始内容存在。不能因解析失败丢字或自动补全关闭标记。原始 HTML 作为可编辑文本保留，不作为可执行文档运行。

### R-DOC-03 语义一致性

实时视图、源码视图、复制与 PDF 读取同一版本、同一方言的内容。允许显示方式不同，不允许某处判为代码、另一处判为列表。链接定义等跨块依赖发生变化时，应更新依赖它们的呈现。

## 5 编辑行为

### R-EDIT-01 实时结构编辑

正文是一块连续编辑区域。标题、段落、引用和列表直接编辑；标记只在需要编辑其语法时显示。代码、数学、图片及表格具有明确的编辑入口和离开方式，不能让用户凭试错寻找光标。

每个按键根据当前编辑归属处理：正文、源码、代码内容、数学源码或表格单元格。同一事件只能产生一次内容操作。焦点变化、重绘和内容提交必须协调；不能让失焦后异步结果恢复旧文字。

### R-EDIT-02 光标与选区

支持鼠标定位、拖选、双击词语、Shift 扩选、跨块选择、macOS 字词/行首尾导航。选区保留方向，中文、emoji、组合字符的移动与删除以可见字符为界，不切开代理对或组合序列。

空段落、代码尾部空行、表格空单元格均有可落入的位置。点击公式采用确定的源码入口：首次进入按对象边界或已有逻辑书签定位；不承诺每个公式像素都对应唯一 LaTeX 字符。列表项、表格单元格和不可编辑对象的选择必须在外观上可分辨。

### R-EDIT-03 输入法

支持真实 macOS 中文拼音组词、候选选择、预编辑退格、取消、标点、混输及候选窗口。组合输入期间不替换活动输入 DOM，不切换编辑归属，不执行结构快捷键；必要的外部命令等待输入完成或显式取消。

保存和关闭不能强行假定已拿到最后一字。真实组合输入未结束时，自动保存可保存最近已提交快照；手动保存、模式切换、关闭须等待系统完成提交，不能自行伪造 compositionend。

### R-EDIT-04 撤销与重做

一次结构动作、一次粘贴、一次表格行列操作和一次全部替换分别是一个历史单元。普通连续输入可分组，一次中文组词是一个历史单元。撤销同时恢复文本、结构、逻辑选区和编辑归属。

实时与源码模式共用根历史，切换模式不清空历史或创建内容编辑。新编辑清除重做分支。系统菜单、快捷键及编辑组件不能维护互不相干的第二条历史。

### R-EDIT-05 段落与标题

实时段落 Enter 拆成两段，Shift+Enter 插入显式硬换行。段首 Backspace 合并相邻兼容段落；连续 Enter 创建的空段落具有独立位置，之后的失焦、保存和重开不能吞掉用户内容。

标题支持 H1–H6；Setext H1/H2 相互转换保留其形式，转其他级别时同时处理下划线。标题内 Enter 拆出普通段落；格式菜单作用于明确块范围，不留下旧分隔符。

### R-EDIT-06 列表与引用

非空项 Enter 续项；空项 Enter 退出一层。Tab/Shift+Tab 改变列表层级时移动完整子树，保留子项关系；没有前一个兄弟时增加层级不生效。现有有序项不批量重编号，新项按前项递增。任务列表续项默认未完成。

引用内 Enter 续引用，空引用行 Enter 退出一层。代码和数学内以 `-`、`1.`、`>` 开头的文字仍是字面内容。多行选区的层级变化按结构集合执行，不按物理行盲目加空格。

### R-EDIT-07 代码与公式

代码块保留语言标识、围栏类型、正文缩进及末尾空行。Enter 始终插入字面换行；无选区且位于已闭合块尾的 Cmd+Enter 在块后新建段落。未闭合围栏或块数学中，该命令不修改内容并提示先闭合，不隐式补关闭符。空块起点 Backspace 转为段落并可一步撤销。代码首尾方向导航可交给外层，跨块删除不留下围栏碎片。

公式支持分式、上下标、根式、矩阵和对齐。编辑数学源码时不运行 Markdown 结构命令。块公式的尾部换行保留，故意不同于已观察的 Typora 序列化。无法渲染时保留表达式并显示错误；渲染失败不影响后续文字输入。

### R-EDIT-08 表格

直接编辑单元格，支持 Tab/Shift+Tab 导航、右键增删行列及对齐。普通 Enter 移到下一行同列，末行时退出到表后段落；Shift+Enter 不插入多行单元格内容，提供简短反馈。Tab 在边界退出，不隐式加行。

竖线、反斜杠与行内代码按 GFM 单元格规则处理。单元格修改只触及该单元格必要语法；行列变更允许改写当前表格。仅有表头也是合法表格；删除表头时提升首个正文行为表头，无正文行则转为空段落。删最后一个正文行保留表头，删最后一列才删除整个表格。初版表格范围选择以文本与单元格范围区分，不提供电子表格公式、合并单元格或多单元格矩阵粘贴；跨单元格纯文本粘贴不会悄悄扩建表格。

### R-EDIT-09 剪贴板与查找

默认复制 Markdown；完整格式元素复制保留其语法，部分文字选区不无条件吞入整个父节点。另提供纯文本及 HTML 富文本复制，均提供确定的回退。Cut 的复制范围与删除范围必须一致；图片复制失败时不删除原内容。

默认粘贴纯文本，Markdown 文本按原文插入；只有图片载荷时走图片插入流程。剪贴板同时有文字和图片时优先文字，另提供“粘贴图片”命令。查找包含隐藏语法、代码和公式，可定位到源码入口；支持大小写开关、前后匹配、单次和全部替换，首版不提供正则模式。

以上行为的具体前后状态和边界见[编辑契约](editing-contracts.md)。

## 6 文件和资源

### R-FILE-01 文件身份与窗口

新建、Finder 打开、应用内打开遵循同一路径。以协调后的文件身份识别重复打开；同一文档激活已有窗口。不同文档的历史、资源、保存请求及恢复空间相互隔离。失效别名或权限不足给出明确结果。

### R-FILE-02 保存与恢复

采用 macOS 文稿语义，提供手动保存、系统调度自动保存、未命名草稿恢复与文稿版本恢复。不得以固定定时器模拟全部系统文稿行为。磁盘保存成功才能确认相应版本已保存；保存旧快照期间继续输入，窗口仍应标记有新修改。

未命名草稿自动保存不弹文件面板。保存失败保留内存与可用恢复快照，允许重试和另存。恢复快照明确其时间和版本；只承诺恢复到最后成功落盘的快照，不能声称崩溃前每个字符都已持久化。

### R-FILE-03 外部变化与关闭

本地无修改且没有活动输入事务时，可以加载外部新版本；本地有修改、活动组词或尚未落盘的资源时，提供保留本地副本、读取外部版或取消。不能静默覆盖任意一方。

关闭、退出、另存和版本恢复须先完成内容屏障。取消关闭后能继续原编辑；用户选择放弃当前修改时不得把未提交的延迟回调重新写入文件。渲染进程退出须保留最后宿主确认的恢复快照，并明确可能损失的未确认编辑。

### R-ASSET-01 本地图片

支持 PNG、JPEG、GIF 和安全的静态 SVG，来源包括粘贴、拖入与文件选择器。已保存文档的新图片复制到 `<文档名>.assets/`，唯一命名并生成相对引用；原图片不被移动或覆盖。

未命名图片进入文档独立暂存区。首次保存先完成资源复制，再提交文稿引用。失败时保留草稿和图片以便重试。另存迁移本应用管理的资源；普通相对引用若会失效，应列出并允许取消或明确接受原引用。

删除引用、撤销插入不自动删除资源文件。已有引用不批量迁移；文件重命名不强制改资源目录名。缺失图片显示路径占位。远程图片保留 URL，不自动联网；PDF 也使用占位。

## 7 输出和界面

### R-PDF-01 固定版式导出

导出输入为最近已提交内容与对应资源的固定快照，包含未保存编辑。导出期间继续输入不改变正在生成的文件。取消或失败不损坏原 PDF，不改变当前文档路径或修改状态。

A4 纵向、四边 20 mm、白底、无页眉页脚页码。中文正文和代码可搜索复制，公式及图片完整。页末标题与后续正文尽可能同页；代码和表格允许跨页但不得裁掉内容。图片等比缩至内容宽度，宽代码采用打印换行，宽公式允许缩放并在超限时给出反馈。

### R-UI-01 外观与操作入口

参考固定 Typora GitHub 主题样本的字体层级、正文宽度、段落和块间距。引用基准必须包含主题文件哈希、字体、视口、缩放与配色。排版参数通过独立设计令牌定义，不通过逐页补丁修改。

系统/浅色/深色及缩放设置不修改源文；深色仅影响编辑。首版菜单提供完整已支持命令，禁用项有一致状态；快捷键与菜单来自同一命令定义。默认无浮动格式工具条。

初始排版目标采用已留存 GitHub 主题的声明值，作为重写的设计令牌起点；这些值不是本轮测得的实际像素，也不意味着已通过视觉验收：

| 参数 | 初始目标 |
| --- | --- |
| 正文字号/行高 | 16 CSS px / 1.6 |
| 正文最大宽度 | 860 px；视口 ≥ 1400 px 时 1024 px，≥ 1800 px 时 1200 px；窄窗不超视口 |
| 正文水平内边距 | 30 px |
| H1/H2/H3/H4/H5/H6 | 2.25/1.75/1.5/1.25/1/1 em |
| 普通块垂直间距 | 0.8 em；空段落还须满足 E12 的独立编辑位置 |
| 列表内缩 | 30 px，语义层级独立于 CSS 宽度 |
| 表格单元格内边距 | 垂直 6 px、水平 13 px |
| 代码字号/圆角 | 0.9 em / 3 px |
| 浅色正文/链接 | `#333333` / `#4183c4` |

参考快照为 `analysis/typora-1.14.10/appearance/github.observed.css`，SHA-256 `0225b3c456252023b46d71b05c7ae592ac247207d5e4aabd99a1f07ef70d02a0`。其字体声明包含 Open Sans、Clear Sans、Helvetica Neue 等回退，实际字体取决于可用字体；新实现须记录实际字体并冻结自己的可分发字体方案，不能把缺失字体的替代效果当成相同视觉。深色与打印令牌分别验收。

### R-UI-02 可访问性

正文可通过键盘完成编辑；焦点可见。表格、公式、图片入口有可理解名称和状态；保持系统高对比度与减少动态效果可用。至少用 VoiceOver 验证段落、标题、表格入口和错误信息的读取及返回编辑路径。

## 8 非功能要求

| ID | 要求与测量方法 |
| --- | --- |
| R-QUAL-01 | 正确性：零静默数据丢失、零未修改区域漂移、零已知输入阻断；失败必须保留恢复路径 |
| R-QUAL-02 | 离线：断网完成编辑、公式、图片、保存、PDF；产品资源随包提供，核心流程无远程请求 |
| R-QUAL-03 | 性能目标：固定本机 Release 包、1 MiB 文字混合夹具，输入到稳定画面 p95 ≤ 50 ms，普通操作 p99 ≤ 100 ms；不把这些数字当作现有成绩 |
| R-QUAL-04 | 规模目标：1 MiB 文件打开可编辑 ≤ 2 s，空文档冷启动 ≤ 2 s；分别重复至少 10 次，记录硬件/OS/缓存状态和原始样本 |
| R-QUAL-05 | 资源目标：1 MiB 混合夹具稳定后应用及其 WebContent 进程合计驻留内存 ≤ 500 MiB；发行包 ≤ 150 MiB；大图片另设解码预算 |
| R-QUAL-06 | 超限处理：> 1 MiB 文档允许提示并以源码方式打开；解析/公式/图片超预算时局部降级，保持可保存和可恢复 |
| R-QUAL-07 | 安全：Markdown/HTML/SVG/链接不获得原生调用权限；只允许声明过的宿主能力，拒绝任意脚本、命令和文件路径请求 |
| R-QUAL-08 | 可诊断性：记录构建身份、文档版本、事务类别、性能和错误码；默认不记录正文、剪贴板或完整个人路径 |

性能夹具须记录字节数、段落/表格/公式数与图片尺寸；纯文本和混合文档分开报告。目标需要真实 WKWebView 验收，不用 Chromium 成绩替代。

## 9 决策状态与验收

已确定：完整归档旧版本；从零开始；本地 Typora 作为 REA 研究对象；保留个人 macOS 编辑器定位。结构编辑框架、具体解析器、公式渲染器、最低系统版本及包版本号属于待验证决策。

所有 R-* 需求均关联[验收方案](../verification/acceptance-plan.md)。技术验证可以淘汰框架，不能悄悄放宽数据安全、输入法或保真要求。需要改变产品行为时，同时修改本需求、行为契约与对应验收样本。
