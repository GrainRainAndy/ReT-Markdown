## 发现、修正及保留的失败

- 消费者回归初稿把禁止定义与有效定义放在相邻两行；原 parser 将其保留为普通段落，初稿断言失败。核对原 parser 后只修正夹具的空行，在产品提取之前即通过；不将其冒称产品 RED。工具新模块缺失的 RED 与之后 2 项 GREEN 单独保留。
- typecheck 发现新工具测试抽出 options 后将 `write: false` 扩宽为 boolean，导致 esbuild 的 `outputFiles` 类型可选。实现者仅改为 `false as const`，未加非空断言或删断言；修复后类型检查、工具 2 项及最终全量单测通过。supervisor 独立发现相同 R1 并确认关闭。原 `typecheck.log` 保留。
- 计划中的 `playwright test web/test` 目录过滤误收集 Vitest `.test.ts`，产生 suite/CSS 解析错误。改为七份 `.spec.ts` 明确入口，不改产品、断言或超时；原 `browser.log` 保留。此为计划验证命令纠正。
- 首轮真正执行 95 项为 **90 通过、5 超时，52.3 分钟**：4 项发生在 beforeEach/setup，1 项发生在可见单元格 click 阶段。`browser-specs.log` 及 `browser-first-results/` 现场保留。源码、原 30 秒预算和断言不变时，定向 5 项在 3.4 秒全部通过；随后完整单轮 95 项在 37.3 秒全部通过。最终 95 不是拼接 90+5。
- 只读电源日志显示 14:46:08 Clamshell Sleep，中间多次 DarkWake，15:48:21 lid/UserActivity Wake，与首轮异常运行窗口重叠。这支持环境中断解释，不构成每个超时的严格根因证明；未修改系统睡眠设置。原文见[协调者睡眠记录](../../build/verification/0.1.0-rc.1-refactor-coordinator/sleep-during-browser.log)，本会话仅保存实际事件的 `power-events.json`，排除 Wake Requests 调度记录。

实现者的 package-lock-only 命令曾重写隐藏的 node_modules lock，已在统一安装前按原哈希恢复；过程和被拦截的错误重建尝试保留在实现交接。随后本会话执行上述获准的干净安装，没有掩去先前副作用。
