## 决策

Ruling: 在既有工作区就地执行且不写 Git 元数据 — 当前 main 上包含此前已批准的未提交实现，.git 在权限配置中只读，用户现次授权推进该工作区 — 如隔离不足导致冲突，需要按文件 owner 和基线快照恢复，不能清理用户修改。

Ruling: 采用上述 IA-10/11 的保守局部编辑规则 — 产品源文保留要求优先于 Typora 的重编号或整文序列化 — 如果交互预期不同，需调整行为契约及对应测试，原源文仍由根历史恢复。

Ruling: 有序列表缩进后，编辑解析器与实际渲染器必须得到相同层级 — 保留原编号，必要时仅在该局部插入空白分隔行，使非 1 起始编号不被渲染为普通正文；不重编号其他条目。

Ruling: Shift-Tab 恢复层级但保留已有分隔空行 — 无法区分该空白此前来自用户还是结构操作，不凭猜测删除；Undo 才是源字节级逆操作。两项有序列表预期同时保留 Lezer 层级检查、增加 renderer 嵌套检查及两次 Undo 原字节恢复。

Ruling: 多行 Setext H1/H2 转换保留内容行与下划线写法；转换为 H3–H6 时，将原标题的软换行连接为空格，形成一个 ATX 标题 — ATX 必须在一条物理行内，不能只转换第一行并把剩余内容降为正文；改动范围仅限原标题块，所有文字与外层容器归属保留。

Ruling: 结构移动提交前必须保持实际 renderer 的全部代码块签名序列（类型、字面正文、info 及数量） — 真实正文误变为关闭围栏时，仅增长受影响围栏的真实开闭标记，未闭合围栏仍保持未闭合。若最终计划仍不能保真，整次结构操作不提交，原文、选区、revision 和历史不变。纯字面缩进保留既有行为。无法保真的复杂组合暂不支持自动结构移动，可在源码模式手工编辑，不将其冒称为支持的成功移动。
