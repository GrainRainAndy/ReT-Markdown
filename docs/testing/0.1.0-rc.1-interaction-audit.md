# 0.1.0-rc.1 编辑交互系统审计

日期：2026-10-21。用户要求先根据 Typora 逆向系统排查反复出现的细节问题，再提出流程化解决方法。本轮仅做静态分析、临时探针与文档，不修改产品代码、不更新运行中的 QA、不写 Git、不操作用户未保存文稿。

## 审计结论

已经复现的问题跨越结构分类、实时投影、输入提交和剪切范围，不能继续按“一个视觉问题配一个局部补丁”组织修复。需要让输入命令和投影共享块归属，明确事件处理权，并验证源文、选区、视图、历史及保存屏障的完整状态转换。

这不意味着现有基础全部失效。Source/EOL/根历史机制已有可用回归；普通闭合代码块的连续空行本轮控制样本正常。要保留这些基础，修复其上层契约与交接点，而不是另建一套文档模型。

## 共同失效模式

1. **语法归属多处重判。** 命令使用 `markdownLanguage`，实时结构使用配置 GFM 的 Lezer，数学和最终渲染使用 markdown-it 规则，部分代码围栏又用文本正则。多解析器不是原罪；问题是它们可以独立决定同一范围属于列表、数学正文、围栏还是普通空行。
2. **操作只有单向规则。** Enter 定义了结构拆分，但删除没有配套决策；复制定义了扩展范围，剪切删除却没有使用该范围。每个分支单测可通过，组合起来不闭合。
3. **把生命周期当渲染时机处理。** EOF、失焦、鼠标交接和 composition 是不同状态边界。修一个 padding 或增加一次延时不能定义谁有权处理输入、何时能替换 DOM、何时能发布保存快照。
4. **验证单位偏向功能点。** 已有真实浏览器和字节/历史检查，不能笼统归为“都是 mock”。但完整生命周期、结构交叉和非理想输入仍缺可追踪契约；总通过数不代表新增语义的相邻操作已经覆盖。

独立覆盖审计还区分了历史已修与当前缺口：表格失焦首绘、跨 cell 选区后输入落错位置、mounted ReplaceAll 撤销分组等已经有修复与回归，不能当作仍未修的缺陷重复汇报。它们共同说明“命令层通过”不等于“实际 UI 入口和连续操作通过”。当前检索未找到真实拖选与 Shift+Arrow 扩选回归，属于有界测试缺口，不是据此证明鼠标拖选损坏。原生窗口失活/返回、系统剪贴板及实际 IME 仍应单列。

审计笔记与 M01—M12 场景、四条原生保存链保留于本轮证据目录 `coverage-notes.md`。其中“IME 取消零提交”只适用于取消后无净内容变化的场景；跨段选择后取消是否保留原选中文本，需要原生行为契约明确，主方案已作此限定。`docs/testing/acceptance-status.md` 仍以 10 月 16 日候选为入口，而后续已有新包和定向补验，属于证据汇总流程风险；历史记录应保留，但“当前候选”需有单一索引，不从多个报告拼接出未经验证的全通过结论。
