## Resolved Important — integer mouse coordinates lost a supported fraction denominator hit

Location: `web/src/live/math-hit.ts`, exact-hit/coordinate-footprint selection; regression: `web/test/complex-math-hit-testing.spec.ts`, “fraction denominator”. The reproduction and failure evidence below describe the pre-fix implementation.

Reproduction: load the existing fixture `😀 前文\n\n$\frac{1}{2}$\n\nend` through its BOM/CRLF input path. Click the left 10% of the rendered `2` Range rectangle, at its vertical midpoint. After the complete mouse gesture and two animation frames, the root caret must be immediately before `2` (UTF-16 offset **17**). The parent's actual browser run instead settles at **8**, the formula reveal/fallback position. Subsequent typing would therefore insert at the wrong source location for the selected glyph. The assertion fails before the insertion/undo portion of this case runs.

Evidence independently read: `build/verification/0.1.0-rc.1/complex-math-20261020/targeted-after-import-fix.log`, lines 11–35 and 107–109: **54 passed, 1 failed**. No browser was launched by this reviewer.

Confirmed cause: integer coordinate quantization in the actual mouse gesture. Independently read `build/verification/0.1.0-rc.1/complex-math-20261020/denominator-gesture.json`: the denominator rectangle spans x **248.3125–255.03125**, y **98.578125–111.578125**; the numerator spans y **84.265625–97.265625**. These rows do not overlap, disproving the earlier overlap hypothesis. At the intended fractional point **(248.984375, 105.078125)**, the helper correctly returns token-relative offset **10**. Actual `mousedown` reports **(248, 105)**, placing x **0.3125 CSS pixels outside** the denominator's left edge. Exact containment consequently finds zero hits and the helper returns `null`; the gesture ends at root offset 8. The existing unit fixture uses integral boxes/coordinates and misses this quantization case.

Resolution reviewed: the landed code retains exact-hit precedence and considers a **1 CSS pixel footprint `[x,x+1) × [y,y+1)`** only when there are zero exact hits and both coordinates are nonnegative integers. Strict rectangle-intersection inequalities exclude mere boundary contact. Exactly one candidate is accepted; multiple exact hits or multiple footprint candidates return `null`. No vertical-center, DOM-order, or broad nearest-glyph selection was introduced for complex formulas. Existing metadata validation and literal-only spacing logic remain in place.

The new `math-mapped-hit.test.ts` regression uses the measured numerator/denominator rectangles and actual integer gesture coordinates: `(248,105)` must return token-relative offset **10**, while `(247,105)` and `(248,113)` must return `null`. These expectations agree with the inspected inequalities. Exact-hit precedence and ambiguous-footprint rejection were validated by control-flow inspection; the added test itself does not separately exercise those two branches. The parent reports unit RED/GREEN. This reviewer did not rerun it. The fix meets the bounded-selection constraints and resolves the code-review finding; the parent still owns complete-gesture browser acceptance, including structural fallback and source/undo behavior.
