## Previous Important findings retained and closed

### Important — a settled context menu could leave raw cell content after outside dismissal

Trigger: edit a formula cell, open its context menu, allow the opening blur/projection to settle, then click an outside control. The opening blur correctly retained the mini editor while the menu owned focus, but closing the menu did not trigger another projection; raw TeX remained after focus had left.

Evidence: `table-blur-review-red.log` records the settled-menu regression failing with one `.cm-editor` remaining instead of zero. The later `table-blur-first-paint-red.log` records the same failure alongside the composition failure below.

Closure: `web/src/live/cell-widget.ts:328` clears the menu and schedules `projectSelection()` in a microtask. The ownership check at line 133 retires an editor only after the focus handoff, retaining a selected cell, real mini focus, or menu focus. Escape/Tab restore cell focus synchronously before the queued projection; menu actions retain their existing root transaction path. Destruction sets `dead` and unregisters observers, so queued projections on a destroyed controller return immediately.

`web/test/table-blur-rendering.spec.ts:99` explicitly waits with the menu open before dismissing it, then checks restored math, no mini editor, unchanged source bytes, zero content commits, and preserved outside focus. **Closed:** included in `table-blur-review-green.log`, 50/50 passed.

### Important — the first static repaint after composition used stale cached HTML

Trigger: compose in a cell, move focus outside while marked DOM is retained, then end composition. Root rendering could refresh while the cell's composition flag still blocked cache regeneration. Retiring the mini editor then painted the previous cache before a later refresh corrected the content.

Evidence: `table-blur-first-paint-red.log` records the MutationObserver assertion failing because an observed static repaint omitted the committed `中`. The earlier composition test passed without observing that first repaint; eventual rendered content alone did not close this finding.

Closure: `web/src/live/cell-widget.ts:197` uses the existing completion callback, clears `cell.composing`, checks `dead`, refreshes the table render cache from current source, then processes deferred actions and projects selection. Cache refresh precedes retirement. No second commit, undo stack, or additional delay timer is introduced by this correction.

`web/test/table-blur-rendering.spec.ts:72` checks marked-node identity and zero commits during composition, observes static DOM mutations, requires every observed rendered result to include the committed text, and verifies one commit, preserved outside focus, and byte-exact root undo. This is DOM mutation evidence, not a captured display frame or real IME session. **Closed:** the strengthened case is included in the 50/50 passing log.

## Table lifecycle, search, and history assessment

The retirement path is reached both after root projection updates and after mini blur. Its microtasks observe completed focus transfers; composition guards protect marked DOM. Nonempty root selections retain the selected mini projection even when the search panel owns focus, while explicit Escape/Tab exits retain the existing endpoint guard. The selected mini receives history-free projection updates under `syncing`; retirement itself only destroys the mini and paints HTML. Source edits, replacement, structural actions, and undo remain owned by the root session.

The reviewed 50-case run contains all seven blur regressions and 43 existing table cases covering search-panel focus, escaped-pipe/astral offsets, source selection, replacement and byte-exact undo, menu keyboard/action/destruction behavior, explicit boundary exits, and composition/math-focus guards. No additional concrete Critical/Important regression was identified in these interactions.

## Native appearance assessment

- `AppearancePreferences.swift` persists `ReT.Appearance` and restores System for missing or invalid values. Light/Dark apply `.aqua`/`.darkAqua` to `NSApplication.shared.appearance`; System removes that override with `nil`.
- `AppDelegate.swift:15` applies the restored preference before installing menus or creating document windows. The delegate and menu controller share one preferences instance.
- `MenuController.swift` gives Settings an explicit target and Command-comma shortcut, validates it before requiring a document, and retains one lazy settings controller. `SettingsWindowController.swift` retains its window on close, refreshes the popup on reopening, and invokes the shared preference through the actual popup action. It is not an NSDocument.
- Settings and document windows and their views introduce no local appearance override. Existing and newly created windows therefore use the application inheritance path, rather than a current-document-only preference. `EditorWebView.viewDidChangeEffectiveAppearance()` forwards the inherited effective appearance through the existing bridge. The bridge's startup `appearance: system` resolves the WKWebView media query. This arrangement is consistent with the real WK startup and transition test.
- Appearance changes reconfigure the editor theme without loading a new session or creating a content/history transaction. The real editor test performs an actual edit, checks bytes/revision/selection/undo state through Light/Dark transitions, returns to System, and verifies a single undo restores the original BOM and mixed-EOL bytes and clean state.

No concrete persistence, startup, multiwindow inheritance, or AppKit settings defect was found. The pre-existing `isReady == false` callback guard alone is not evidence of a startup regression; ordinary startup passes the real WK test. A theme change specifically during bridge loading was not reproduced here and is not promoted to a finding.
