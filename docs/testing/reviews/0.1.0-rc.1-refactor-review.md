## 发现与关闭

**R1：新增工具测试类型检查失败。** `web/test/tooling.test.ts:51` 读取 `output.outputFiles[0]`，但同一测试的 `options.write` 被普通对象推断为 `boolean`，经 spread 传给 esbuild 后，返回类型不保证 `outputFiles` 存在。本轮 `typecheck.log` 明确报 TS18048。这不表示产品运行失败，但违反方案要求的 typecheck exit 0，阻断本次重构验收。

**R1 已关闭。** 实施者仅将 options 的 `write: false` 改为 `write: false as const`，未删除断言或使用非空断言绕过检查。已读取 `fix-typecheck.log`、`fix-tooling.log`（2/2 通过）及修正后的 `unit-final.log`（302 通过、1 可选跳过）。原失败 `typecheck.log` 保留。`final-code-sha256.json` 与首次冻结清单仅此测试文件不同，全部 179 项重新核对一致；该测试最终 SHA256 为 `d85698466f9c83a3febf1a363f72f37677d3b36168a820e8518ef61bbed88493`。

**验证入口纠正。** 方案中的 `playwright test web/test --workers=1` 同时收集 Vitest 的 `.test.ts`，导致 suite/CSS 解析错误，见 `browser.log`。改为显式列出七份 `.spec.ts`，未修改产品或测试断言。此项为验证命令错误，不作为产品 RED。

**浏览器验证已完成，首轮超时证据保留。** 显式七份 spec 首轮为 90 通过、5 超时（52.3 分钟），见 `browser-specs.log`；四项发生在 beforeEach，一项发生在可见单元格的 click 阶段。冻结源码、原 30 秒超时和断言不变时，五项定向重跑全部通过（3.4 秒），见 `browser-failed-recheck.log`。随后完整七份 spec 的单次运行 **95/95 通过（37.3 秒）**，见 `browser-final.log`；该最终数字来自完整单轮，不是拼接 90+5。

已独立读取协调者保存的 `sleep-during-browser.log`：14:46:08 进入 Clamshell Sleep，中间多次 DarkWake，15:48:21 才发生 lid/UserActivity Wake，覆盖首轮异常运行窗口。这支持环境中断解释，但不是对每项超时的严格根因证明。保留首轮及重跑日志，不通过放宽预算掩盖异常。
