# 0.1.0-rc.1 表格退出渲染与外观设置

2026-10-20。用户报告表格内光标移出后公式渲染延迟，并要求随后在设置中提供 Light / Dark 切换。不写 Git，保留之前的复杂公式映射和间距修复，不覆盖旧 QA。

## 表格退出的根因与修复

此前单元格 mini editor 主要在另一个单元格被激活时销毁；`projectSelection` 没有在编辑焦点和根选区都离开时恢复静态渲染。点击正文、Escape、外部控件均取得 RED：两帧之后仍有一个 `.cm-editor`，而没有恢复公式。问题是缺少退出生命周期，不是 KaTeX 排版耗时。

现在在选区投影刷新时检查编辑所有权：根选中的单元格、真实 mini 焦点或表格菜单焦点继续保留；其余单元格退出编辑并用当前渲染结果重绘。mini blur 在微任务中观察已完成的焦点交接。组合输入期间不销毁标记 DOM，结束后在原有屏障回调中刷新；不新增等待计时器，不产生内容事务或第二套历史。

6 项新增浏览器用例覆盖正文点击、Escape、外部焦点、最新公式内容与单次根撤销、最后一格 Tab 退出、组合输入失焦后完成再渲染。最初三项 RED，修复后六项 PASS；包含原有表格、搜索、菜单、公式命中和组合输入的首轮 46 项 PASS。

## 外观设置约定

应用菜单增加 `Settings…`（Cmd+,），无文档时仍可打开。使用轻量的原生 AppKit 设置窗口，Appearance 提供 System / Light / Dark；System 保留现有默认行为。偏好按应用持久化，在创建文档窗口之前恢复；通过 `NSApp.appearance` 统一控制设置、所有现有/新文档窗口及 WebView。复用已有外观变更回调，避免重建编辑会话和撤销历史。PDF 使用独立白底输出，不随屏幕外观改变。

### 独立审查发现与回归

首轮 158 项浏览器通过后，Astra high 审查发现两个 Important，均通过新增真实浏览器回归确认：

- 菜单拥有焦点时正确保留 mini editor，但菜单关闭到外部控件后没有再次刷新；已在菜单关闭后排队观察最终焦点并投影，不抢回外部控件焦点。
- 组合输入期间跳过了渲染缓存刷新；结束时可能先重绘旧缓存，下一次刷新才补上新内容。原来的最终状态断言通过，新增 MutationObserver 捕获第一次静态重绘后取得 RED：该次内容没有已提交的“中”。现在清除组合标志后先从当前源文刷新缓存，再处理延期动作和退出投影。不新增计时器、内容提交或撤销记录。

见 `table-blur-review-red.log`（菜单失败、原先较弱的组合输入断言通过）、`table-blur-first-paint-red.log`（两项均失败）、`table-blur-review-green.log`（50/50 PASS）。最终 7 项新增退出用例与 43 项既有表格用例全部通过；[最终独立审查](reviews/0.1.0-rc.1-table-blur-and-appearance-review.md)关闭两项发现，无开放 Critical/Important。MutationObserver 验证的是 DOM 重绘内容，不冒称真实 IME 或显示帧时间测量。

### 原生交互复验

只使用本轮 `fixtures/table-blur.md`，不编辑用户文稿：

1. Cmd+, 成功打开轻量原生 Settings，初始为 System。
2. 实际 popup 选择 Light：设置窗口变浅色；新建的空白文档具有白色画布。
3. 打开自有表格夹具，点击公式单元格，AX 显示 `$x^{2}$` 的 mini editor；点击正文“After”后，mini entry 从 AX 中移除，截图恢复排版后的 `x²`。Escape 退出也维持恢复的渲染态。
4. 关闭并重新打开 Settings，保留 Light；选择 Dark 后设置窗口变深色。再次关闭/重开仍显示 Dark，通过 Window 菜单选回原表格文档，截图确认原有文档画布及标题栏同步变深色。实际偏好域读回 `ReT.Appearance=dark`。
5. 测试结束恢复 System，偏好域读回 `system`；关闭本轮创建、已核对为空的 Untitled/Untitled 2，只保留验收文稿和设置窗口。验收文件始终为 92 字节，SHA-256 `d4a78c90b3dbdd9ca8e7bd10854302b0b9127d8e7836aea58f44a4dc2d8abc1c`。
