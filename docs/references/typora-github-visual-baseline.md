# Typora GitHub 主题视觉基准

日期：2026 年 10 月 14 日。目标：本机 `/Applications/Typora.app`，版本 1.14.10，build 7786；主题菜单中的 `Github`。

该基准用于 ReT Markdown 首版排版验收，替代此前自行提出的 760 px 阅读宽度建议。它固定当前版本的主题规则，后续 Typora 升级不自动改变本项目的验收基准。

## 实际观察

通过 Computer-Use 在 Typora 新建独立样本窗口，选择 `Github`，使用原生打开对话框载入 [排版样本](typora-github-sample.md)。检查了页面上下两部分，包括中英文正文、三级标题、引用、列表、代码、表格和数学公式。原有文档内容未编辑。

实际界面呈现居中正文、宽松行距、一级与二级标题下的细横线、蓝色链接、灰色引用文字和左侧边线、浅灰代码块，以及具有细边框和交替底色的表格。行内公式与块级公式均可见。

以下数值来自主题 CSS 声明，不是从截图反推的物理像素，也没有宣称已测得运行时计算样式。屏幕缩放、编辑器缩放、字体回退和应用基础样式可能影响最终观感。验收时应使用相同样本、相同逻辑窗口宽度和 100% 编辑缩放比较。

## 主题规则

| 项目 | 当前 GitHub 主题声明 |
| --- | --- |
| 根字号 | 16 CSS px |
| 正文字体 | Open Sans 优先，后备 Clear Sans、Helvetica Neue、Helvetica、Arial、Segoe UI Emoji、SF Pro、sans-serif |
| 中文字体 | 通过系统字体回退获得字形，具体回退字体未作运行时测量 |
| 正文颜色与行高 | `#333333`，1.6 倍行高 |
| 阅读容器 | 居中，默认最大宽度 860 px；内边距 30 px，底部留白 100 px |
| 宽窗口 | 视口宽度达到 1400 px 时最大宽度 1024 px；达到 1800 px 时最大宽度 1200 px |
| 标题字号 | H1 至 H6 分别为 2.25、1.75、1.5、1.25、1、1 em |
| 标题间距 | 默认上下各 1 rem，粗体；H1／H2 有 `1px solid #eee` 底边线 |
| 标题行高 | H1 1.2，H2 1.225，H3 1.43，其余默认 1.4 |
| 段落及主要块间距 | `0.8em 0`；嵌套列表上下间距为 0 |
| 列表缩进 | 左内边距 30 px |
| 链接 | `#4183c4` |
| 引用 | 左侧 4 px `#dfe2e5` 边线，左右内边距 15 px，文字 `#777777` |
| 表格 | 1 px `#dfe2e5` 边框，单元格内边距 `6px 13px`，表头及交替行底色 `#f8f8f8` |
| 代码 | 0.9 em，1 px `#e7eaed` 边框，3 px 圆角；代码块底色 `#f8f8f8`，行内代码底色 `#f3f4f4` |
| 代码块间距 | 上下外边距 15 px，上内边距 8 px，下内边距 6 px |
| 打印字号 | 主题的打印规则将根字号设为 13 px |

容器宽度指 CSS 中的 `max-width` 声明，不能直接等同于扣除内边距后的净文字宽度。实现时需结合盒模型与同宽度样本比对。

## 产品适配

浅色模式以该主题为视觉基准。深色模式保持相同的字号、间距、层级和组件结构，使用适合深色背景的配色；本轮读取的主题文件不能证明 Typora GitHub 自带深色配色。

正文的 Open Sans 常规、斜体、粗体及粗斜体资源在本机主题目录中可用。产品实现应提供离线字体资源和中文系统回退。主题中用于导出的远程字体加载指令不作为产品行为继承。

PDF 采用相同的视觉语言，参考主题的 13 px 打印根字号，并继续遵循已确认的 A4 纵向、四边 20 mm 版心规则。屏幕阅读容器的 30 px 内边距不能叠加为额外的纸张边距。当前 Typora 的实际 PDF 输出未在本轮导出观察。

样本中观察到的公式编号属于 Typora 的公式配置，不因参考主题而自动纳入本项目需求。标签页、侧边栏、工具条和联网行为也不因参考外观而引入。
