## 3. 确认的正确性问题

### B01 · P1 · 输入新围栏后焦点未交接，后续字符未进入文稿

**证据：L2 实测，阻断验收。** 空白文稿、实时模式，逐键输入三个反引号，按 Enter，继续输入 `xhello`，最后切到源码模式。

实际 checkpoint 依次为一个反引号、两个反引号、三个反引号、`"```\n\n"`；最终源码仍只有这 5 个字符，没有 `xhello`，也没有 RecoveryDraft 或恢复提示。新代码块已经出现，但活动元素一直是外层 ProseMirror，未转入局部 CodeMirror；Enter 仍执行了正文拆段逻辑。

定位：`editor/surfaces/rich.ts:1066` 附近的 `refresh` 只为 `owner.kind === "source"` 转换字面域归属，没有覆盖正文输入刚形成代码块的交接。此归因与运行状态一致，具体修复还需跟踪事务/选区重建。

证据：`E/render-probes/keyboard-fence-{after-ticks,after-enter,after-x,final-source}.json` 及同名 PNG；独立脚本为 `acceptance.spec.ts`。

关闭条件：从空段落手工输入反引号/波浪号围栏及语言名，Enter 后直接继续键入，无须再点击代码区；输入、选区、Undo/Redo、模式切换、保存重开均一致。必须在 Chromium 和最终原生包各验证一次。关联 R-EDIT-01/06/07、R-QUAL-01。

### B02 · P1 · 空特殊块的正文插入点不合法，正常输入触发恢复

**证据：代码块 L2 实测；数学边界 L1 探针。** 以下源码进入实时模式，点击字面内容区并输入 `x`：

- 无尾 LF 的 `"```js"`。
- 空引用代码块 `"> ```\n> ```"`。
- 空列表代码块 `"- ```\n  ```"`。

三者均弹出“字面内容无法安全表示”。生成的恢复候选分别为 `"```jsx"`、`"> ```\nx> ```"`、`"- ```\nx  ```"`，把字面内容插到了语言标签或关闭围栏前错误的位置。草稿保留了字符，故这里不声称静默丢失，但正常编辑已被阻断。无尾 LF 的 `"```"`、`"~~~"`、`"$$"` 对 `x` 也在留存模型探针中失败；已有开围栏后 LF 的顶层块是正常对照组。

定位：`editor/surfaces/commands.ts:583` 从空 mapping 决定插入点，`:588` 只从已有正文 segment 推断容器前缀，`:669` 的安全校验随后拒绝；`rich.ts:346` 进入恢复流程。

证据：`E/render-probes/{bare-fence,empty-quote,empty-list}.json/.png`，模型 `results.json`。

关闭条件：空正文需有合法插入锚点，必要时仅补开围栏后的换行与所在容器前缀；未闭合块不得因此隐式闭合。输入、连续 Enter、撤销、保存重开都可用，恢复候选不得改变用户输入的语义。关联 E06/E17/E26、R-DOC-02、R-QUAL-01。

### B03 · P2 · 重入关闭请求直接丢失 delegate 回调

**证据：当前 Swift 产品源码的隔离 CLI 实测。** 挂起 `prepareAssetsForSave`，连续两次调用 `canClose`，再释放保存准备。第一个观察者收到 `[false]`，第二个始终为 `[]`。

定位：`native/Sources/ReTPreview/Document.swift:197` 的 `guard !closeActive else { return }`。第一次请求等待 flush、保存或选择时，第二个调用者没有任何完成通知；若它属于退出/关闭全部流程，会有永久等待风险。真实窗口菜单重入尚未完成复验，不能把该风险写成已实测的 Cmd+Q 死锁。

证据：`E/lifecycle-probes/lifecycle-audit.swift`、`lifecycle-audit.stdout.txt`。现有 `LifecycleTests.swift:43` 覆盖的是第一次完成后再关闭，未覆盖重叠调用。

关闭条件：每个关闭请求恰好完成一次；重复关闭/关闭全部/退出有确定的合并或拒绝结果，取消不影响继续编辑，保存队列不会在放弃后写入未提交内容。关联 F06/F07/F13、R-FILE-03。

### B04 · P2 · 不齐 GFM 表格的列数呈现错误

**证据：L1 投影及 HTML 输出实测，Typora 原生对照。** 三列表头 `| A | B | C |`，分隔行 `|---|---|---|`，正文仅 `| one |`：当前实时投影和导出都只有一个正文单元格。反之，一列表头的正文 `| a | b | c |` 会显示三个格。

定位：`editor/surfaces/projection.ts:373`、`editor/render/document.ts:100` 直接遍历源行的所有 children，未统一按表头列数补齐/截断。`rich.ts:900` 的导航按表头列数寻址，但缺失格不存在，存在提前离开表格的风险，导航后果本轮未做 GUI 验证。

Typora 对同一三列表头/一格正文样本实际呈现 3 个正文格，后两格为空。证据：`E/render-probes/results.json`，Typora 本轮 AX/截图观察见第 5 节。

关闭条件：呈现与导航按表头列数一致；缺格提供可编辑空位置，超额格按方言隐藏；不编辑时原始字节不变，编辑缺格时仅物化必要语法。关联 R-DOC-02/03、R-EDIT-08。

### B05 · P2 · 链接图片在实时投影中丢失链接语义

**证据：L1 实测，交互后果为代码追踪。** `[![logo](logo.png)](https://example.com)` 的 image 节点没有 link mark，导出却保留 `<a><img></a>`。同一分支也使 `**$x$**` 的行内公式丢失 strong mark。

定位：`editor/surfaces/projection.ts:253` 创建 image/inline_math 时未继承传入 marks；`editor/main.ts:992` 的链接点击依赖 `a[data-url]`，实时链接入口因此缺失。

关闭条件：内联对象继承外层语义；链接图片能通过已有 Cmd-click/上下文入口打开；实时、复制和导出的链接语义一致。关联 R-DOC-03。

### B06 · P2 · 首行合法缩进被误建为空段落

**证据：L1 实测。** 打开 `"  paragraph"`、`"  # Heading"` 或首行缩进两空格的围栏，投影产生 `gap + paragraph/heading/code`。源文没有空行，导出也没有额外空段落。

定位：`editor/syntax/projection.ts:69` 将首块前、同一行的缩进误当成独立空行。会影响首块布局与首个可编辑位置，不能只用 CSS 消除间距。

关闭条件：仅真实空行创建独立 gap；同一行合法缩进保留为语法前缀，不新增编辑结构。关联 R-DOC-03、E12。

### B07 · P2 · 组合输入期间 flush 立即失败，没有等待提交后续跑

**证据：跨层静态确认；真实系统 IME 未完成。** `editor/main.ts:445` 在 composing 时立刻回复 pending；`native/Sources/ReTPreview/EditorHost.swift:159` 消费回调并返回失败；`Document.swift:214` 随即进入“尚有未确认输入”的关闭选择。compositionend 后不会重新完成原来的保存/关闭请求。

该保护避免把未提交输入冒称已保存，但未实现 E02 / R-EDIT-03 的等待契约。关闭条件：真实中文候选活跃时保存/关闭进入 pending，正常候选提交后继续原动作；超时或失败可明确重试/取消；取消后焦点与输入保持。不能用合成 composition 事件替代系统输入法验收。

## 6. 进阶要求及可执行验收标准

这些要求细化本次用户提出的 Typora/Github 和自定义样式方向，不扩大到复制 Typora 全部功能，也不把图片/PDF既定规则改成参考应用的偶然行为。

| 编号 / 顺序 | 要求 | 通过条件 |
| --- | --- | --- |
| X01 · 修复期 | 对齐日常编辑操作 | 为段落、标题、列表、引用、代码、数学、表格定义进入/编辑/失焦/退出状态；覆盖逐键形成语法、粘贴、菜单、源码切换、反向选区、撤销、保存重开。以 Typora 同版本实测为参考，差异明确登记，保留本产品原文保真要求 |
| X02 · 修复期 | 特殊块具有稳定交互 | 代码语言驱动离线高亮，未知语言退回纯文本；更换语言不改变代码正文或选区。公式活动时可编辑源码，失焦收起源码只留预览，点击能回到合理书签；渲染错误仍可编辑，不把错误提示永久当作正文 |
| X03 · 外观验收 | 内置 Github 视觉基线 | 固定主题哈希、实际字体/回退、100% 缩放、窄/常规/宽窗、浅/深色和样本；逐项比对标题层级、正文宽度、间距、列表、引用、代码、表格、公式、选区。检查聚焦前后高度与滚动稳定，记录偏差及原因；不能只写“总体类似” |
