## B08：关闭取消后的首次真实拼音提交残留预编辑字母（P1）

**影响：** 正文出现用户并未提交的拼音字母，且进入磁盘及恢复记录；属于内容正确性问题，阻断当前验收。以下是 CUA 驱动真实 macOS 中文拼音的两次复现，不是合成 DOM composition 测试；另请求了实体键盘交叉确认，结果待回填。

复现步骤：

1. 在实时正文中通过系统拼音输入并提交中文，保存文稿。
2. 再键入 `ni` 或 `nihao`，保持系统预编辑状态，点击红色关闭按钮。
3. 窗口暂不关闭；按空格提交候选后，出现“保存对文稿的更改？”提示。
4. 点击取消；不再次点击正文，直接键入 `ni` 并按空格。
5. 预期只追加 `你`；实际追加 `ni你`。再次正常输入 `ni`→空格只追加 `你`。

第二次复现把“取消”与后续输入拆成两次 CUA 调用，中间读取窗口状态，仍复现，不能仅解释为一个批次发键过快。取消后 AX 焦点为 HTML content；首个 `ni` 输入时状态却不是“正在输入”，字数从 25 增为 27，提交候选后为 28，并可见 `ni你`。正常组合时显示“正在输入”，字数在提交前不增长。

磁盘证据：显式菜单保存后，再次读取 `RET-IME-1024.md` 确认两处 `ni` 残留。冻结副本 `ime-persisted-observation.txt` 与 `ime-evidence.json` 保存了原文、哈希和复现次数。原文为 `RET-IME-1024\n\n你好世界你好ni你你你ni你你`；最后一个“你”来自为人工复核准备的第三次关闭前候选提交。两处 `ni` 应均不存在。

定位线索（**尚非已证实根因**）：[Document.swift](../../native/Sources/ReTPreview/Document.swift) 关闭取消调用 `releaseInput()`；[main.ts](../../editor/main.ts) 的 `finishFlush` 设置 `workspace.inert = true`，`flushRelease` 清除 inert/hold 但未显式恢复编辑表面焦点；[rich.ts](../../editor/surfaces/rich.ts) 依赖表面上的 `compositionstart` 标记组合态。需要记录取消后的实际焦点、DOM selection、composition/beforeinput 时序，区分首个事件丢失、焦点恢复和 ProseMirror 状态。不能只补合成事件测试后宣布修复，应复跑上述真实系统输入法步骤，并扩展到代码/公式/源码模式。

验收方不修改产品实现。修复后需要新候选身份、同一最小复现的原生反证、完整 Markdown 字节及关闭保存回归。

## 必须保留的异常观察

**O-1024-01：保存和 PDF 目的地面板曾持续禁用 Save。** 原主样本在关闭保存面板取消之后，后续 Cmd+S 面板显示有效文件名，但 Save 禁用；改名、重开面板、切换目录（证据目录与 `/private/tmp`）后仍观察到禁用，PDF 面板同样如此。展开时 New Folder 也禁用。后续创建全新文稿、执行最小取消保存流程均成功；再通过文件菜单回到原样本，保存与 PDF 都恢复成功。未修改或重启候选应用，未能稳定重现最小触发条件，根因未定。因此保留为间歇性疑点，不宣称“所有保存流程无误”，也不直接归因到关闭状态机。

Typora 对照：同一证据目录中保存按钮及新建文件夹按钮可用，确认保存后返回文稿。对照文件最终为 0 字节，未达到文本内容回读验证要求，故该对照只证明当时面板按钮可用，**不作为 Typora 文本保存正确性的证据**。未修改其原有用户文稿。

**O-1024-02：输入与自动化会话异常。** 首次 `typeText('!')` 后源码没有该字符，随后连接服务重启；重新连接、重复公式失焦并改用 `pressKey('exclam')`，出现全角 `！` 且精确落在后段落。Typora 中一次 Cmd+S 工具调用表现为正文追加 `s`，改用文件菜单才能可靠进入保存。因此输入法状态与输入工具路径必须单独确认，不能把此次 `typeText` 未写入当作已确认的产品丢字缺陷。
