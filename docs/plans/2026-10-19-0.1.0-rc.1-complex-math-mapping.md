# Complex math source mapping

Goal: exact UTF-16 insertion boundaries for rendered TeX glyphs, preserving source bytes, undo ownership, and KaTeX layout. Public API remains `mathHitOffset(dom, source, block, x, y): number | null`.

## Renderer contract (table integration)

Every successfully rendered formula has a `span` wrapper with `data-math-from` and `data-math-to`: original-document UTF-16 half-open token interval, including dollar delimiters. Call `mathHitOffset(wrapper, original.slice(from, to), block, x, y)` before focus removes the rendered DOM; add the returned relative offset to `from`. `data-math-source` contains JSON-encoded original token source (HTML-escaped), allowing exact stale-source rejection without normalizing CRLF in an HTML attribute. Wrapper attributes exist even when precise provenance is unavailable. Errors retain the existing error rendering. Clipboard output remains bare MathML.

Existing KaTeX HTML glyph spans carry `data-math-start` / `data-math-end` relative to the raw token start, and `data-math-map` JSON tuples `[textFrom, textTo, sourceFrom, sourceTo]`. Text offsets address the span's actual UTF-16 text; source intervals are half-open. These attributes are renderer-owned, never accepted from TeX HTML extensions. No attributes are needed on MathML. Consumers should use the helper rather than interpreting glyph maps.

## Architecture and invariants

1. `math.ts` captures a start and end source position for each TeX UTF-16 unit during Markdown tokenization. Inline positions come from `inlineRange`/`inlineOffsets`; block positions are collected while markdown-it's container-adjusted line boundaries are available, before trimming. CRLF, removed table pipe escapes, indentation and quote/list prefixes are discontinuities, not inferred substring matches. Starts and ends are separate so a boundary never crosses removed trivia.
2. A small `render/math-katex.ts` adapter imports the pinned KaTeX 0.19.0 source parser/builders. The public dist engine is not imported by production code. All private imports use exact `.ts` paths required by package exports; extensionless imports worked in Vitest but failed the first production esbuild attempt. `math-katex-private.d.ts` describes the inspected private boundary and the package's untyped Unicode generators. No project/build configuration changes are required. Scope interception of the native leaf HTML builders (`mathord`, `textord`, `atom`) to one synchronous render and restore in `finally`. Carry parser source locations to their corresponding existing virtual SymbolNodes. Validate original input provenance and exact lexical spelling; reject definition/assignment macros and ambiguous repeated locations. Do not map generated macro-body locations.
3. Annotation changes only existing span attributes at serialization, after native layout and character combination finish. No leaf wrappers, classes, changed AST types, inserted TeX, modified trust settings, or disabled character combination. For merged literal runs, map only source-contiguous characters whose original literal slice and known leaf locations verify the complete run. Otherwise retain fallback. The adapter is the only dependency-private boundary. A package-version mismatch disables metadata; tests compare attribute-stripped output with native KaTeX and exercise fail-closed behavior.
4. `mathHitOffset` reads source-tagged text Range rectangles, selecting the before/after source boundary of the actual glyph under the pointer. Command glyphs map atomically to command start/end. Distinct vertical structures are never flattened into text order. Only verified single-line literal runs may bridge inter-glyph operator spacing. Ambiguous overlap, missing provenance, malformed/stale metadata, hidden/degenerate rectangles, structural SVG/rules and clicks outside glyphs return `null` for existing reveal behavior.

## Supported and fallback cases

Fractions, superscripts/subscripts, nested groups, root index/radicand, Greek commands, normalized minus, whitespace and multiline/container source offsets are supported through native leaf provenance. Matrix cells, sum limits, accent bases and literal `\\text` contents use the same path when their leaf locations survive. Fraction bars, radical signs, accent marks, generated operator names and synthetic macro expansions are not assigned guessed source locations. Definition/assignment macros disable mapping for that formula; duplicated or non-original leaf locations are rejected. Failures never broaden `trust:false`, `maxExpand:1000`, or `maxSize:50`.
