> **For agentic workers:** 实施时使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐项执行并记录结果。用户已于 2026-10-17 明确批准重构；勾选框仅在取得对应证据后更新。

**Goal:** 在不改变编辑、复制、渲染与导出行为的前提下，消除已确认的重复代码，整理直接依赖声明，为后续本地提交做准备。

**Tech Stack:** TypeScript、Node ESM、markdown-it、esbuild、Vitest、Playwright；本轮不修改 Swift。

**Spec:** [需求基线](../specs/2026-10-14-markdown-editor-design.md)，重点为 F01/F02 源文保真、F06 复制、F08 共享语法、F15–F17 PDF 和 N04 离线运行。本文件定义本次有限重构的具体范围。

## 重点审查的五类风险

1. 链接定义中包含相对路径、`file:` 或禁止的自定义协议：解析、复制和系统浏览器打开的职责不能混为一谈；由任务 1 的真实渲染/复制回归覆盖。
2. CSS 含中文、反斜线或引号：打包后字符串必须保持原内容；由任务 2 的实际 esbuild 输出执行检查覆盖。
3. 性能工具读取 CSS 时记录哈希：提取插件后仍须记录原始字节，不能只保留 TS/JS 的 `captureInputs`；由任务 2 的读取钩子检查覆盖。
4. 性能计数与导出特殊入口：保留 `operation-count` 插桩、导出测试的 `?inline` 和原 CSS 列表；由任务 2 的计数回归及显式导出运行时覆盖。
5. `RET_CHROMIUM` 未设置或为空：各调用点原有 `||` / `??` 行为不能被统一改写，性能脚本 CLI/cache 优先级也不变；任务 2 只集中回退路径，不集中选择策略。

**接口：**

```ts
rawCssPlugin(options?: {
  inline?: boolean;
  onRead?: (absolutePath: string, bytes: Uint8Array) => void;
}): import('esbuild').Plugin;

chromiumFallbackPath(homeDirectory?: string): string;
```

`rawCssPlugin` 默认仅匹配 `.css?raw`，`inline: true` 时额外匹配 `.css?inline`。读取原始字节后可通知 `onRead`，再以现有生产实现的 `export default ${JSON.stringify(cssText)}` / JS loader 输出字符串模块。不改变 CSS 内容；工厂每次返回独立插件实例。

`chromiumFallbackPath` 默认读取现有 `process.env.HOME`，返回当前固定 `chromium-1228/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing` 完整缓存路径。各调用点继续自行使用原有 `RET_CHROMIUM || fallback` 或 `RET_CHROMIUM ?? fallback`。它不启动、不发现、不下载浏览器。`measure-performance.mjs:106–114` 的 CLI/env/cache 发现逻辑原样保留，避免将本轮去重变成浏览器选择策略调整。
