# 编辑交互质量：按契约、状态转换与证据推进

2026-10-21 执行注：用户后续以“进行推进”授权实施。本文件中的“尚未改动”“仅审计”等语句描述方案形成时的状态；当前修复、独立审查和验收状态以[执行记录](../testing/0.1.0-rc.1-interaction-implementation.md)为准，日常操作入口见[缺陷处理流程](../testing/editor-interaction-workflow.md)。

> **For agentic workers:** 执行修复时使用 Superpowers 的系统排错、测试驱动、独立审查与完成前验证。本文件当前交付流程与分阶段方案，不表示任何修复已经执行。用户既有模型分工保持：架构、高难度及关键审查 Astra high；一般实现与测试工程 6.1 Sol high；不无任务保留代理。

**Goal:** 让编辑器的输入、块结构、实时视图、选区、撤销和保存共同满足可测试的行为契约，避免不断由用户发现相邻边界问题。

**Architecture:** 保留唯一 Source、局部补丁、EOL 元数据及根历史；在其上建立共享的结构上下文、明确的事件归属与操作计划。投影消费结构信息，不再独立猜测隐藏范围；浏览器与原生验收各自承担能证明的部分。

**Tech Stack:** Swift/AppKit/WKWebView、TypeScript、CodeMirror 6、Lezer、markdown-it、Vitest、Playwright、Computer Use、REA 静态证据。

**Spec:** [产品需求](../specs/2026-10-14-markdown-editor-design.md)、[架构约束](../architecture/2026-10-14-native-editor.md)、[本轮审计](../testing/0.1.0-rc.1-interaction-audit.md)、[Typora 机制证据](../references/2026-10-21-typora-editing-mechanisms.md)。

## 全局约束

- macOS 为首版目标；不增加多标签页或侧边栏。
- Markdown 是持久化权威；不保存 HTML、不整文 AST 重序列化、不统一用户未修改的符号/空行/缩进/混合 EOL/BOM。
- 全部内容编辑归同一根事务与历史；表格 mini view 不建立另一份权威文档。Typora 的节点序列化/局部历史不直接照搬。
- 不为本方案升级依赖、重写整个编辑器或引入另一套状态框架。
- 历史包与证据保持不变；原生测试只用自有夹具。QA 固定路径与 ID，源身份另存；运行中不替换包、不自动退出含未保存文稿的应用。
- 当前执行仅限审计、证据和方案，未修改产品代码、未写 Git。

## 一、先建立可追溯的行为契约

每项行为先写成一个完整场景，不能用“体验和 Typora 一样”作为预期值。场景至少记录以下字段：

| 字段 | 必需内容 |
| --- | --- |
| 身份 | case ID、对应需求、Typora 版本/证据来源、待测源码身份与依赖版本 |
| 初态 | 原始字节、模式、光标或有方向选区、块/容器结构、焦点 owner、是否 composition、已保存状态 |
| 操作 | 真实键盘/鼠标/菜单序列；明确 Enter 与 Shift/Cmd+Enter、Backspace 与 Undo 的区别 |
| 结果 | 允许修改的源文区间、EOL/BOM、最终选区与 owner、应可见的正文/空行、可接受的结构变化 |
| 生命周期 | 操作后、离开该块后、切换模式后、Undo/Redo 后、保存/重开后分别必须成立的断言 |
| 证据等级 | Typora 原生观察 / 安装包静态分支 / 产品需求决定 / 当前尚未知 |

静态源码发现某个分支，不能自动把它升级为 Typora 实测行为。需求与 Typora 不同，以已确定的需求为准并记录原因；未知的段落合并、代码块退出等策略不能悄悄由当前实现决定。

第一份场景集以代码围栏为完整切片，覆盖反引号/波浪号、三/四字符、不匹配关闭标记、未闭合 EOF、正文内类似围栏的文字、引用/列表容器。现有普通闭合围栏控制样本必须保留，避免把所有空行都当作语法分隔。

## 二、收拢三处决定权

### 结构归属

建立一个共享语义适配层，让编辑命令和投影消费同一份上下文。具体实现审查后再定文件接口；职责必须明确：

- 区分正文、标题、列表、引用、代码、数学、HTML、表格单元格与未知语法。
- 对范围给出 opening/body/closing、容器前缀、是否闭合，以及空 EOF 是否仍归该块；不能只给一个 kind。
- 数学、代码、HTML 等字面区域先确定归属，再考虑列表续项或 Markdown 删除操作。现有默认快捷键也必须经过相同的适用范围检查。
- Lezer 继续服务增量语法与编辑，markdown-it 继续服务渲染；用一致性样本验证二者的上下文解释，避免简单要求“一律换成某个 parser”。缓存与失效策略属于适配层，禁止每个组件重新全文解析再自行判定。

代码围栏投影必须从真实语法标记得到关闭范围；没有关闭标记就不得隐藏一段形似围栏的正文。内容范围可以是空区间，空 EOF 仍必须获得正确的编辑归属和样式。

### 操作与选区

一次编辑先决定“处理者、前置条件、修改范围、替换内容、最终选区、历史边界”，再提交一个根事务。没有处理权时显式交给约定的下一级，不允许自定义 Enter 与默认 Markdown Backspace 使用不同的块定义。

成对定义拆分/合并、入块/出块、缩进/反缩进、复制范围/剪切范围、结构改变/撤销。它们不必全部互为数学逆操作，但必须明确差异；不能默认“一次 Backspace 等于撤销 Enter”。

复制、剪切删除与粘贴插入要共享同一个已解析范围。IA-06 的验收不是“剪贴板有 Markdown”，而是同一场景中复制出的源文、删除的源文和粘贴落点一致。

### 输入与投影生命周期

统一记录焦点归属（root / cell / panel 等）、composition 状态、当前源版本和待处理投影更新。投影更新只作用于它计算时对应的版本和范围；DOM 替换前取得命中位置，替换后恢复逻辑选区，不能继续使用旧盒子。

IME 冻结边界必须早于 CodeMirror 可能删除跨块选区的阶段；真实事件次序、observer 与 handler 的先后要有探针证明。composition 的取消、结束、焦点转移和保存屏障分别有结果，不用任意 setTimeout 当作正确性条件。代码块、表格和公式使用一致的生命周期规则，组件只实现各自局部投影。

## 三、验证单位改为操作序列

每个修复至少经过以下检查点，适用项不得只留静态截图：

1. **输入前：** 固定 raw bytes、选区、模式、owner 与根 revision。
2. **输入后：** 真正经过按键/DOM 路径；检查源补丁、选区、提交数量与结构，不只检查 `textContent`。
3. **离开后：** 实际点击另一块，检查内容/空行/样式与 owner，源文和历史不能因此改变。
4. **模式往返：** live → source → live，检查字节、选区映射和既有历史；未知语法必须仍可编辑。
5. **撤销重做：** 一次结构操作按契约撤销；BOM、各个 EOL 和原始局部语法一起恢复。
6. **保存重开：** 对需要持久化的场景读取磁盘字节及 hash，重开同一源码身份的 QA 验证，而不是只看网页快照。

至少保留这些可组合不变量：

- 仅移动焦点、改变配色/缩放或切模式，不修改 Source，不额外发布内容 commit，不增加 undo 事件。
- 不相关区间的字节完全不变；被允许改变的范围必须由操作计划解释。
- 无中间编辑时，undo/redo 恢复规定的 Source、选区及编辑归属；不能只比较最后字符串。
- 默认源文剪切后在原位粘回，恢复原始源文；若因结构策略不能满足，必须有明确场景规则，不能由重复标记偶然决定。
- projection 切换不能隐藏真正的字面内容，或把代码内部空行变成普通正文。
- composition 期间 barrier 保留开始前最后已提交内容与选区；结束后将最终净变化合并发布。取消且最终源文无净变化时不发布内容提交；取消对原先选中文本的保留行为应由原生场景明确，不能一概假定所有取消都零提交。不能把合成事件通过当作实际输入法验收。

## 四、用小矩阵覆盖交叉风险

不穷举所有组合。每个结构先覆盖本地边界，再覆盖相邻结构交接；发生过缺陷的组合保留为固定场景，其他组合用确定种子进行补充探索。

| 维度 | 最小取样 |
| --- | --- |
| 结构 | 普通段落、标题、列表/引用、代码、数学、表格、HTML/未知语法 |
| 位置 | 块首/中/尾、空块、空行、未闭合、EOF、嵌套容器、跨块选区 |
| 操作 | Enter、Backspace/Delete、Tab、方向键/鼠标、复制/剪切/粘贴、Undo/Redo、模式切换 |
| 输入 | ASCII、中文、emoji/组合字符、真实 IME 开始/确认/取消；EOL 采用 LF 与带 BOM 的混合样本 |
| 生命周期 | active/inactive、root/cell/panel 交接、滚动离开/返回、保存屏障、保存重开 |

第一批必选序列：代码 EOF Enter→键入→移出→返回→Undo；数学负号位置 Enter/Backspace；跨段选择→IME开始→barrier→确认/取消；格式文字 cut→paste→Undo；段落 Enter→Backspace→失焦；表格查找→cell编辑→root正文→撤销。每个序列都记录未被修改区域与 owner，不以测试数达标替代覆盖说明。

选区入口至少包含真实拖选、Shift+Arrow、正向与反向选择；程序直接 dispatch 选区可用于隔离语义，但不得成为唯一入口。原生保存链至少包含：输入A→保存→输入B→保存完成（磁盘A、内存B仍脏）；含图片的未命名稿首次保存取消/失败/重试；另存成功→继续编辑→撤销→分别重开旧/新文件；外部修改 clean/dirty 冲突→明确面板选择→磁盘与内存核对。详见本轮 `coverage-notes.md` 的场景矩阵。

## 五、分层证据与发布门槛

| 层级 | 必须证明 | 不能替代 |
| --- | --- | --- |
| 纯状态/单元 | 块范围、操作计划、补丁、EOL/BOM、选区/历史/屏障、无关区域不变 | 实际 DOM caret、系统输入法 |
| 真实浏览器 | 真键盘与鼠标、active/inactive、计算样式、caret/命中范围、视口与 root/cell 交接 | AppKit 菜单、WKWebView 原生 IME、磁盘真实保存 |
| 固定 QA 原生 | 实际输入法、菜单/快捷键、鼠标、系统剪贴板、保存重开 | 以截图推断未执行的字节或历史检查 |
| 发布记录 | 源码输入身份、依赖、包清单、QA current.json、每项场景证据与未验证项一致 | 把旧包测试或历史报告写成当前全通过 |

修复合入门槛：

- 有修复前可重复 RED，且失败原因与发现相符；修复后同一场景 GREEN，控制场景保留。
- 围栏/数学/列表等上下文变更后，运行受影响的相邻结构序列；不只跑新增测试。
- 新行为独立审查同时检查交互契约与实现；高难度语义/IME用 Astra high，常规代码与测试用 Sol high，完成即关闭代理。
- 变更冻结后运行完整自动检查，再构建固定 QA；构建期间不并发写发布资源。
- 规定的原生场景有实际结果；工具故障写 pending，不能降级为浏览器通过后仍标 native passed。
- 当前候选只有一个入口索引，链接不可变历史记录；P1 不关闭、原生关键项未验证或证据与源码身份不匹配时，不宣称完整正式版通过。
- 不通过删除失败用例、放宽容差、把期待值改成当前实现来消除 RED。需求确有变化时，先改契约并明确保留哪些历史断言、为何不同。

## 七、续审后明确的执行规则

本轮补齐的 [Typora 原生参考](../references/2026-10-21-typora-runtime-contracts.md)及 IA-08—11，使以下决定更具体。它们仍是修复方案，尚未改动产品或接入 CI。

1. **入口先归一。** 自有 keymap 排在普通优先级，而 CM Markdown keymap 是 `Prec.high`。先列出并确认实际处理者，再把键盘、菜单/API 归一为带 owner 和块上下文的语义 intent。字面换行、段落拆分、列表续项、段首合并、空块退出和单元格导航是不同 intent；默认 CM 命令仅在适用范围内作为明确 fallback。不得只修 API newline，然后用其单测认证真实 Enter。
2. **结构关系作为操作结果。** 列表缩进的目标是层级变化，缩进宽度按父项内容列和容器内位置计算；引用前缀、编号宽度、Tab 列和子项都参与。标题转换消费完整 ATX/Setext 结构，不逐物理行无条件加井号。原生 TY-08 的子项改同级、重编号行为不直接复制，先规定 ReT 前后树及允许的局部修改范围。
3. **给已明确样本一个确切预期。** 建议 IA-07 的普通非空段首 Backspace 按 TY-05 合并前后段落；IA-09 的 Setext H1→H2 保持写法，仅改下划线。围栏/数学正文按字面输入，不被列表命令接管。空块退出和跨结构选区另列规则，不能推广为一组普适的 Enter/Backspace 逆运算。IA-10/11 的重编号、跨块后缀归属和不透明块转换仍待逐项定案。
4. **观察源文、活动视图、稳定视图三个结果。** TY-10 的活动 AX 展开和磁盘源文不同，TY-06 的数学尾部序列化也与活动 CM 不同。ReT 验收要分别记录三者及选区/owner/commit，不把活动 `textContent` 当唯一正确性证据，也不为了复制 Typora 的规范化引入第二份权威状态。
5. **每个缺陷走固定状态流。** `reported → reproduced → contract_defined → red_recorded → fixed → reviewed → required_native_verified → closed`。适用的原生门槛未完成则不能越过；不需要原生的纯逻辑项记录理由。失败或源码身份变化时回到对应环节；探针“断言坏结果确实出现”属于 reproduced，不是正式产品测试通过，也不自动算 red_recorded。
6. **把登记变成修复交付的一部分。** 本轮 `continuation/contracts-proposed.json` 已给 IA-01—07 建立来源、初态、动作、源文/选区/视图/历史/屏障断言、证据及关闭条件；未知 oracle 明确为 null。该文件是拟议登记表，不是已实现 runner。正式执行时逐项落入现有 unit/browser/native harness，并将 IA-08—11、真实入口和场景的证据补齐。不得把 null 自动转换为跳过后仍算通过。

```mermaid
flowchart LR
  A[记录初态与实际入口] --> B[复现并保留证据]
  B --> C[确定需求与参考行为契约]
  C --> D[正确预期的失败回归]
  D --> E[最小修复与相邻结构检查]
  E --> F[操作到失焦及撤销保存的验证]
  F --> G[独立审查及适用原生验收]
  G --> H[同一候选身份下关闭问题]
  F -- 失败 --> B
  G -- 不满足门槛 --> C
```

可立即采用的最小工作单以 IA-09 为例：初态 `Alpha\n=====\n\ntail`、光标 0；从 API 与原生菜单执行 H2；期望为 `Alpha\n-----\n\ntail`、仅下划线范围改变、仍只有一个标题与 tail、光标仍在 Alpha 逻辑位置；移出、模式往返、Undo/Redo、保存重开分别核对。混合 EOL/BOM 样本独立取样，不能从此 LF 样本推断通过。当前实现应先在正式测试中因“旧下划线成为正文”失败，修复后再逐门槛关闭。
