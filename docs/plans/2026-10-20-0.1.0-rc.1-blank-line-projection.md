## Bounded policy

1. Use existing syntax gap ownership; do not reinterpret Markdown containers or change parser spans. Within each consecutive run of ordinary root whitespace gaps, the first row remains the structural separator. Later rows remain real editable CodeMirror lines after selection leaves. Leading/trailing runs retain the same first-row convention; the terminal empty CM line is an editing position, not another collapsed source gap.
2. Quote-marker gaps retain existing quote activation behavior. Blank rows owned by lists, fenced/indented code, tables, math, or other opaque parsed blocks do not become root editable gaps.
3. Ordinary structural gaps reveal only when selection/composition touches their own line, excluding the next line's start. Extra rows do not depend on selection.
4. Add a scoped zero-padding line class only to visible ordinary root blanks and unowned empty EOF lines. Code/list/quote/table insets and source mode retain their existing rules.
5. Keep the current collapsed block margin calculation (including the reported 16px native baseline; actual em lengths depend on editor font/zoom). Persistent extra rows add their measured line height, but remain transparent to margin collapse, preventing two paragraph margins around each row.
6. Preserve the existing viewport wrapper filtering and height-map mechanism. No DOM measuring loop, synthetic block widget, newline replacement, source mutation, or extra history transaction.

## Implementation and validation

- `decorations.ts`: identify consecutive ordinary gap rows, retain extras, scope caret alignment, and pass extra row positions to spacing.
- `spacing.ts`: allow preserved blank rows to be transparent to margin calculation while CodeMirror measures their actual line boxes.
- New focused unit and browser tests: inactive/active rows, unchanged ordinary separator geometry, one line-height per extra row, actual glyph-left alignment and mouse editing, source/container insets, mixed EOL/BOM bytes and undo, long-document scrolling/mode transitions.
- Run focused units/typecheck and browser checks when Chromium ownership is available. Coordinator owns the complete suite and native validation.

Existing AC9 browser cases at widths 1000/1400/1800 use four LF characters between paragraphs yet expect pure Markdown renderer spacing. They will require an intentional baseline update for the new extra-row policy; do not weaken or edit them here. The new test separately retains the renderer comparison for an ordinary two-LF separator and asserts added line heights for extra rows.
